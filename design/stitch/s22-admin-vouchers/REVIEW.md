## Implementation notes

- Field errors come from the API `code` and `details`; `VOUCHER_CODE_TAKEN` goes under the code field, `PLAN_NOT_FOUND` / `PLAN_NOT_ACTIVE` under the plan select. Other codes show in the dialog or form alert as in F4a.
- Amount: text field validated as a decimal string with `src/lib/money.ts` (> 0, ≤ 1000, up to the API's precision). Days 1–365, limit integer ≥ 1 (on edit ≥ `redemptionCount`).
- Code field: LTR, stored upper case by the API; the form only checks 4–40 of letters, digits, dashes when not empty.
- Dates: `datetime-local` shown in the browser's local time, sent as ISO UTC; «إزالة التاريخ» sends `endsAt: null`. Only changed fields go in the PATCH.
- Status badge is derived for display (decision 10): متوقف if `!isActive`; else مستنفد if used = limit; else منتهي if past `endsAt`; else لم يبدأ if before `startsAt`; else فعّال. The list filter «فعّال» maps to `status=active` (so it includes منتهي, لم يبدأ and مستنفد rows; see question 1).
- No create `idempotencyKey` (decision 11): the submit button is disabled while the request runs (frame 2c).
- Copy button: `navigator.clipboard.writeText`, then «تم النسخ» for ~2s with `role="status"`; if the clipboard is blocked, select the code text and show «تعذّر النسخ، انسخه يدويًا».
- Redemption email links to `/admin/users/$userId`; a null `userEmail` shows the short user id. `subscriptionId` is shown as a short id (`ShortId`) or «-» for balance codes. «تحميل المزيد» uses `cursor`.
- Reuse `ReasonDialog` (reason required) and the `Badge`, `Field`, `FormControls` pieces. Desktop table becomes cards below `md` (no horizontal page scroll). Update DESIGN.md (admin) only after approval.

## Open questions

1. **Filter naming.** The API filters on `isActive` only, so «فعّال» also lists expired, not-started and used-up codes (their badge says otherwise). Keep the filter as «فعّال / متوقف» (as briefed), or label it «مفعّل / موقوف» to separate it from the badge?
2. **Active toggle and the «إيقاف الكود» button do the same thing.** The board shows both (as requested): the switch is saved with the other fields, the header button is a one-step shortcut with its own reason dialog. Recommendation: keep only the header button and show the state as the badge, to avoid two paths.
3. **Where the generated code appears.** Board shows a dedicated result view after create (frame 3); the alternative is to land on the detail page with a banner. Result view chosen so the code is the single focus.
4. **Trial value label** uses the plan's Arabic name («احترافي · 7 أيام»); the day count needs ICU plurals (يوم واحد، يومان، 3 أيام، 11 يومًا).
5. **Not drawn:** redemptions list loading/error (same pattern as 1b/1e inside the card), the copy-failure message, the open plan select list, native date-time pickers, tablet width.
