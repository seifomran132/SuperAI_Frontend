## Implementation notes

- Query `GET /admin/agents`; edit by `PATCH /admin/agents/{key}` with only changed fields plus `reason`; fresh idempotency is not specified for this endpoint (confirm). Plans come from the admin plans list; when it fails, omit `planKeys` from the PATCH.
- Save is allowed when on with no plans (warning only, per the brief). On `PLAN_NOT_FOUND`, refetch plans, drop vanished keys from the selection, keep the other input. On `AGENT_NOT_FOUND`, offer to refresh the list.
- List chips: first 3 plan names, then «+N» with an `aria-label`. Row shows the warning variant when `isEnabled` and `planKeys` is empty.
- Dialog scrolls inside (max 90% height, pinned footer) on desktop; the board draws it at full height. On phones it is a bottom sheet.
- Text goes to `src/i18n/admin.{ar,en}.json`.

## Deviations and open questions

1. **Name in Arabic.** The error catalog says «المساعد» for agent, so the page and nav are «المساعدون». The chat picker group in F13 is «مهام متخصصة». Confirm.
2. Plan names are fictional samples; all plans are listed and inactive ones are marked (answered).
3. «آخر تحديث» kept: `updatedAt` is in the DTO (answered).
4. **Order direction** («الأصغر أولًا») and the 0-1000 range are assumed from the modes form; confirm with the backend. No length limits for labels/descriptions are drawn.
5. **Stage 3 fields: designed (see Update).** Open: the DTO gives only `ready`, not why. The board derives "missing model" from null model fields and says generically that models must be switched on and priced. If the API can return the reason, show it. The contract says an empty margin uses the models' own margins (not a global default), and the board follows the contract.
6. No create or delete: agents are defined by the backend, so the page has no «new agent» button.
7. Switch position is mirrored for RTL (on = knob toward the end/left), as in S22.
