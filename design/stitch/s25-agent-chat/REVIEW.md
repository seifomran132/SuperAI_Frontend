## Desktop frames
1. Picker: 1a mode menu with the group «مهام متخصصة» and «مصمم جرافيك» + description (new chat); 1b new-chat empty state with an agent card under the usual suggestions; 1c the menu inside an existing conversation (adds «يبدأ محادثة جديدة.»).
2. Header: 2a title «مصمم جرافيك» (first question, brand name); 2b full conversation, title «مصمم جرافيك · مقهى الندى», history (questions as text, answers as normal user bubbles: text, logo thumbnail, colour swatches) above the active input. No header button: the way out is the sidebar (drawer on phones) «محادثة جديدة», as in DESIGN.
3. One frame per input type (chat column only, no sidebar): 3a/3b `brand_picker` (normal; «علامة جديدة» disabled with the limit text and «عرض الباقات»); 3c/3d `text` (required with counter; optional with «تخطّي»); 3e/3f `choices` (formats; styles with «أو صِفه بكلماتك»); 3g to 3j `upload` (empty optional; uploading + failed; ready with a PDF; max reached); 3k to 3m `colors` (rows with «الأهم», «ألوان من شعارك» chips, picker + hex; invalid hex; at max); 3n/3o `fields` (filled; empty, «بدون نص»); 3p `summary` (brand), 3q/3q2/3q3 `summary` of the request («علامة أخرى»; no prices; balance notes only: none when `ui.estimate` is null, «رصيدك يكفي لتصميم واحد من 2.» when `fitsVariants` is between 1 and `variants`-1 with «يبدو جيدًا» enabled, and the warning «رصيدك لا يكفي لهذا التصميم.» with «الرصيد» link and «طلب رصيد» when `fitsVariants` is 0, with «يبدو جيدًا» disabled and «تعديل» / «علامة أخرى» still available); 3r `design_saved`; 3s `none`.
4. States: 4a sending, 4b `400 VALIDATION_FAILED` (value kept), 4c `409 AGENT_STEP_MISMATCH` (short note «تغيّرت المحادثة، فعرضنا السؤال الأخير.» above the latest question, since the client reloads the messages itself), 4d `409 AGENT_NOT_AVAILABLE`, 4e `409 BRAND_KIT_LIMIT_REACHED`, 4f network error with «إعادة المحاولة».

## Deviations from DESIGN.md
1. (Dropped 2026-11-10: the header button was removed; the sidebar/drawer «محادثة جديدة» is the way out.) The deviations that remain are the next two.
2. Agent chip on messages uses the brand-fill chip (like the image-mode marker in S17), not a mode colour, since an agent is not a mode.
3. The input panel replaces the composer and reuses its look (white, `#7C8799` border, radius 24, soft shadow) but is taller; the summary and colour panels scroll inside on phones (max-height) with the action buttons fixed below.

## Implementation notes
- Only the newest agent message renders its input; older messages render text only. Reply bubbles come from the server's `content`/`answer`; no optimistic bubble.
- `choices` without `allowText` send on tap; with `allowText` the text box has its own send. `brand_picker` cards send on tap. `upload`: «تخطّي» only while no files are chosen; «متابعة (n)» disabled while any file uploads.
- Counters: `<bdi dir="ltr">` or `.ltr`; hex in `dir="ltr"`. Use the same formatters as S24.
- Reuse the built S24 parts (colour rows, drop zone, tiles, `suggestedColors`); the panel is in `features/chat/components/agent/`.
- Phone: the dock sticks above the keyboard with safe-area padding.

## Decisions (user, 2026-11-10)
1. Keep both labels «تصميم» and «مصمم جرافيك»; the heading «مهام متخصصة» and the descriptions separate them. 2. Colours may be empty: «متابعة» stays enabled. 3. ## Implementation notes for the balance notes
- Arabic count words for «يكفي لـ…»: 1 «تصميم واحد», 2 «تصميمين», 3 «3 تصميمات»; the total is a Western digit (`variants` is 1 to 3). «يبدو جيدًا» sends `confirm` only when `fitsVariants` > 0 (the backend still decides with `INSUFFICIENT_BALANCE` at run start, stage 4).
- «طلب رصيد» opens the contact options as in S14; «الرصيد» links to /balance.
