- Screen ids: **none (hand-built)**. - Design system: Bayan Design System v2 (`assets/36af8002bd434fa8b291a1daf21f24ce`), source [design/DESIGN.md](../../DESIGN.md). The admin shell, list, table, badge, field, reason-dialog and bottom-sheet patterns are S22's, copied from its `build.mjs` and extended.

- Files: `desktop.html` / `desktop.png` (1520px board, 27 frames), `mobile.html` / `mobile.png` (21 frames at 375px). Both are generated by `node build.mjs` in this folder; PNGs were rendered with headless Chrome (Playwright). Board titles and small notes are annotations, not UI. Sample data is fictional (names, `example.com` emails, codes).

## Desktop frames

1. **List** `/admin/vouchers` with two tabs «أكواد فردية» and «مجموعات الأكواد» (batches selected, tab kept in the URL). Table: name (link), kind, value, used / quantity with a progress bar, total value, status, end date, row chevron (mirrored). Rows cover all five badges. Status filter «مفعّل / موقوف» (S22's wording), «إنشاء مجموعة أكواد», «تحميل المزيد».
   1b loading skeleton, 1c empty, 1d filtered empty, 1e error with retry.
2. **Create balance** `/admin/vouchers/batches/new`: 2a prefix `eid` typed, live example `EID-7KQ2-XH9M`, total 50 × 5.00$ = 250.00$ above the submit button; 2b defaults (10 codes, no prefix): example `LAM7A-7KQ2-XH9M` labelled «مثال على الكود» with a line saying that is the default prefix.
3. **Create states**: 3a trial (plan + days, quantity, no money total, only a plain summary); 3b total over 10,000$ (100 × 150.00$): amount field in error, total box in danger with message, submit disabled; 3c field errors (name, quantity 2, prefix, reason); 3d form-level failure (`VOUCHER_CODE_TAKEN`: generic message, retry makes a new key); 3e sending («جارٍ الإنشاء…», button disabled).
4. **Batch detail** `/admin/vouchers/batches/$batchId`: 4a active (progress: used / quantity, credited of total value; Download CSV; «إيقاف المجموعة»; summary; settings for end date and note; codes table with used/unused filter, copy button, «إيقاف الكود» on unused active codes only; one code off while the batch is on; one row just copied; a turned-off code shows «تفعيل الكود» while the batch is on). 4b just created (notice and primary Download CSV in front, 0 / 50). 4c batch off (banner, «تفعيل المجموعة», turn-on dialog).
5. **Live-codes warning** before every CSV download: 5a dialog, 5b downloading state.
6. **Reason dialogs**: 6a turn off one code (reason error shown), 6b turn off batch, 6c save settings (change summary + reason), 6d turn a code back on.
7. **Single voucher detail for a batch code**: no redemption-limit field and no end-date field (the note stays), a notice with «فتح المجموعة», and a «المجموعة» link in the summary.
8. **Failures**: 8a codes loading, 8b codes error (rest of the page intact), 8c used filter with no results, 8d CSV download failed, 8e batch loading / `VOUCHER_BATCH_NOT_FOUND`.

## Mobile frames (375px)

م1 list as cards with progress, م1b loading, م1c empty, م1d error, م2a create balance, م2b defaults, م2c trial, م2d over 10,000$, م3 field errors + form failure, م4a just created, م4b detail (progress, then codes as cards, then summary and settings), م4c batch off, م5 CSV warning, م6a turn off code, م6b turn off batch, م6c save settings, م6d turn a code back on, م7 batch-code voucher, م8a codes loading, م8b codes error, م8c CSV failed. Measured in headless Chrome: no element extends past any frame, so no horizontal page scroll; tables become cards (S22 did the same, no inner scroll containers).

## Decisions (user, 2026-11-09)

1. A code turned off can be turned back on: «تفعيل الكود» on its row, only while the batch is on, with a reason dialog like turning off (frames 6d, م6d). It is the same `PATCH /admin/vouchers/{id}` with `isActive: true`.
2. Single voucher page for a batch code hides the redemption limit and the end date (the batch owns the end date); the note stays.
3. Mobile batch detail order: progress, codes, summary, settings.
4. Batch off: unused codes stay neutral with no per-code action (frame 4c).
5. Download CSV stays available on an off batch.
6. «مستنفد» stays for a fully redeemed batch.
7. `10,000.00$` (with the separator) and `YYYY-MM-DD HH:mm` date fields are confirmed.
8. No Stitch pass; the hand-built boards stand.

## Implementation notes

- Money: total = quantity × amount with `src/lib/money.ts`; `<Money>` for display; block above 10,000.00$ in the browser, and still show a `400 VALIDATION_FAILED` on `amountUsd` on the amount field. The design writes the limit as `10,000.00$` with a thousands separator (confirmed). Credited progress bar = `creditedUsd / totalValueUsd` (the board draws it from the counts, which agree only when every code is worth the same).
- Idempotency: one UUID per open form, new after success or any value change; `IDEMPOTENCY_KEY_REUSED` reuses existing `dialog.keyReused` text. `VOUCHER_CODE_TAKEN` shows the generic alert (3d) with retry.
- Prefix: input accepts either case, stores upper case; the example updates as you type; empty prefix uses the brand/backend default `LAM7A`, labelled as an example.
- Dates: masked text fields `YYYY-MM-DD HH:mm` (the built `DateTimeField`, which differs from S22's board that drew `dd/mm/yyyy`), device time, sent as ISO UTC; «إزالة التاريخ» sends `endsAt: null`.
- Batch status badge is derived: متوقف if `!isActive`; else مستنفد if `redeemedCount == quantity`; else منتهي if past `endsAt`; else لم يبدأ if before `startsAt`; else فعّال. The list filter maps to `status=active|inactive`.
- Code row status: مستخدم if `redeemedAt`; else متوقف if `!isActive`; else غير مستخدم. Row action: «إيقاف الكود» on unused active codes, «تفعيل الكود» on off codes, none on used codes. With the batch off, unused codes show a neutral badge and no per-code turn-off (frame 4c), because the batch already stops them.
- CSV: fetch with bearer token, blob download named from the batch name; the warning dialog opens before every download; failure keeps the page and shows 8d.
- Copy button: `navigator.clipboard`, then «تم النسخ» with `role="status"` for ~2s.
- Codes and emails: `<bdi dir="ltr">` / `.code` isolated; row links the email to `/admin/users/$userId`.
- Tabs on `/admin/vouchers`: `role="tablist"`, state in the URL (`?tab=batches`). The singles tab is S22's list unchanged.
- Audit log needs Arabic labels for `voucher_batch.exported` and the batch actions (plan decision 10); not drawn here.
